How can this be done?•Manually write System.out.println(…) before each method call.•Way too much work.•Very prone to errors (“oops, I forgot these 500 method calls in that file…”).•Extremely high viscosity (what if there will later be a need to change the “style” of what exactly should be printed?).•Manually modify the source code of each method so that it has System.out.println(…) as the first statement in its body.•Still: a lot of work, very prone to errors, very high viscosity.•No need to write System.out.println(…) before each method call.•Problem: what if we don’t have access to the source code of the classes?..•Parse the entire program code to get the abstract syntax tree (AST), and transform that AST as follows: insert a System.out.println(…) before each method call.•Fun, but difficult.

Activation records: summary•An activation record is the runtime representation of an activation of a function•It stores function’s formal parameters, local variables, return value, and other info•Among this other information:•Dynamic link (also known as “control link”): a pointer to the activation record of the caller•Static link (in languages that support first-class functions): a pointer to the frame of the outer function in which the function was defined•During the execution of a program, activation records are arranged in a stack•When a function is invoked, its activation record (a.k.a. “stack frame”) is pushed on the stack•When a function returns, its activation record is popped off the stack, which ends the lifetime of everything stored in the record•The dynamic link points to the previous record in the stack

Parameter passing modes•Procedure parameters convey what types of data the procedure uses, and what types of data the procedure produces•Terminology: inflow and outflow of information•Modes:•obs – data is observed (inflowing)•observed parameters should not be modified in the procedure body•observed parameters can be expressions•when a procedure is called, the value of an observed parameter will be placed in a local variable•out – data is output/produced (outflowing)•output parameters should not be read before being initialized in the procedure body•actual arguments for output parameters should be variables•upd – data is updated (both inflowing and outflowing)•actual arguments for output parameters should be variables

Summary: recipe for interpreters1.Have a precise definition of the object language abstract syntax, paying attention to syntactic categories of the abstract syntax.2.Decide if the object language needs an environment model, a store model, or some other model.3.Determine the types of the object language and its models, making explicit types possibly concealed within the synctactic categories. Each such function is a mapping from a syntactic category to a semantic domain.The interpreter defines a precise semantics for the object language!

Definiteness•The accuracy of the description of a language’s syntax and semantics is important for the usability of the language.•Vagueness in descriptions:•the programmer cannot rely completely on the language•different implementations can choose to resolve ambiguously described features differently – with unfortunately consequences for program portability•Earlier versions of C++:•int x = 0; int result = f(x) + g(x);•The order of evaluation of subexpressions was not explicitly defined in the language specification!•Hence: the output of this program was not guaranteed to be consistent across different C++ implementations!

Combination orthogonality•If one member of sort A can be combined meaningfully with one member of sort B, then any member of sort A can be combined with any member of sort B•Example:•Assume there are three kinds of declarations:•plain declarations (var x;)•initializing declarations (var x = 10;)•initializing constant declarations (const x = 10;)•and there are many kinds of types:•basic•array•struct•…•Combination orthogonality: any kind of declaration can be used for any kind of type

--- Page 407 ---

Sort orthogonality•Everywhere where one member of sort A is allowed meaningfully, any member of sort A should be allowed meaningfully•This is a special case of combination orthogonality, in which one axis is kept constant•Example:•assume that a language has structs containing basic types•then: it should also have structs containing arrays, structs containing structs, and so on

Number orthogonality•Everywhere where a member of sort A is allowed meaningfully, zero or more members of sort A should be allowed meaningfully•Example: where one declaration is allowed, zero or more declarations should be allowed•Number orthogonality often requires special syntactic support•Java:•string s = ”hello"; •string a, b;

Orthogonality•Orthogonality should not be considered a replacement for simplicity•The tradeoff between these two goals is hard to quantify and it appears to be a central decision in language design!•It is not always clear whether it is better to have a few simple concepts with general restriction-free composability or a larger collection of less simple concepts with several minor restrictions•The balance between orthogonality and simplicity can be called “predictability”•The combination of language features should not provide unexpected results•Based on the knowledge of the language primitives, it should be possible to predict the effect of their various combinations

Weakly typed•Variables can be implicitly coerced to different types without explicit conversion by the programmer•This can lead to unexpected behaviour•Examples of languages:•JavaScript•PHP•Perl

Strongly typed•Strict type-checking rules are enforced in order to ensure that operations are performed only on compatible types•Examples of languages:•Haskell•Rust•Swift

Structurally typed•Compatibility of types is determined by their structure rather than their explicit declaration•Example:•Two types are considered compatible if they have the same set of fields and methods, regardless of their names or declarations•Examples of languages:•TypeScript

--- Page 450 ---

Nominally typed•Type compatibility is based on explicit type declarations and/or names•Example:•Types are considered compatible only if they are explicitly declared as the same type•Examples of languages:•Java•C++•C#

--- Page 451 ---

Duck typed•Duck typing focuses on an object’s behaviour rather than its type•Example:•suitability of an object for a particular operation is determined by whether it supports the required methods or behaviours, rather than by its explicit type•Examples of languages:•JavaScript•Python

Operational semantics
First assign 1 to y, then test whether xis 1. If it is, then stop, otherwise update yto be the product of xand the previous value of y, and decrement xby one. Now go back to testing whether the new value of xis 1 and repeat.
y = 1;while (x != 1) { y = x * y; x = x – 1; }

Denotational semantics
The program computes a partial function from states (values of all program variables) to states: the final state will be equal to the initial state, except that the value of x will be 1 and the value of y will be equal to the factorial of the value of x in the initial state.
y = 1;while (x != 1) { y = x * y; x = x – 1; }
